# vSphere Control Plane Job — Step-by-Step Walkthrough

What the `<cluster>-vsphere-cp` Job does, in order, when ArgoCD syncs the provisioning chart.

## Prerequisites (created before the Job runs)

ArgoCD sync-waves ensure these exist before the Job starts at wave 9:

| Wave | Resource | Purpose |
|------|----------|---------|
| 0 | Namespace | `<cluster>` namespace |
| 1 | Pull Secret | Red Hat pull secret (or ExternalSecret) |
| 2 | ClusterDeployment | Hive cluster record |
| 3 | AgentClusterInstall | Assisted Installer config (networking, provisionRequirements) |
| 4 | InfraEnv `<cluster>-cp` | Generates the CP discovery ISO |
| 4 | InfraEnv `<cluster>-workers` | Generates the workers discovery ISO |
| 6 | Secret `<cluster>-vsphere-cp-creds` | vCenter username/password (or ExternalSecret) |
| 6 | ServiceAccount + Role + RoleBinding | RBAC for the Job to read InfraEnvs and patch Agents |
| 6 | BareMetalHost(s) | One per bare metal worker host (if any) |
| 7 | ConfigMap `<cluster>-vsphere-cp-govc` | The govc shell script mounted into the Job |

## Job spec

- **sync-wave**: 9 (runs after all prerequisites are ready)
- **backoffLimit**: 2 (retries up to 2 times on failure)
- **activeDeadlineSeconds**: 7200 (2-hour hard timeout)
- **restartPolicy**: OnFailure
- **image**: `quay.io/openshift/origin-cli:latest` (configurable via `vsphereControlPlane.images.govc`)
- **serviceAccount**: `<cluster>-vsphere-cp` (scoped to read InfraEnvs, patch Agents in the cluster namespace)

## Step-by-step execution (govc script)

### Step 1: Install govc

Downloads the govc binary from GitHub releases, matching the pod's CPU architecture (x86_64 or arm64). Version is configurable via `vsphereControlPlane.govcVersion`.

```
curl → /tmp/govc.tar.gz → /usr/local/bin/govc
```

### Step 2: Configure vCenter connection

Sets govc environment variables from the Job's env (sourced from values + the credentials Secret):

| Env var | Source |
|---------|--------|
| `GOVC_URL` | `vsphereControlPlane.vcenter` (or vcsim service if simulator enabled) |
| `GOVC_USERNAME` | Secret `<cluster>-vsphere-cp-creds` key `username` |
| `GOVC_PASSWORD` | Secret `<cluster>-vsphere-cp-creds` key `password` |
| `GOVC_INSECURE` | `vsphereControlPlane.insecure` |
| `GOVC_DATACENTER` | `vsphereControlPlane.datacenter` |
| `GOVC_DATASTORE` | `vsphereControlPlane.datastore` |

### Step 3: Wait for CP InfraEnv ISO URL

Polls the `<cluster>-cp` InfraEnv CR every 10 seconds (up to 60 attempts / 10 minutes) until `.status.isoDownloadURL` is populated. This URL is generated by the Assisted Installer once the InfraEnv is processed.

```
oc get infraenv <cluster>-cp -n <cluster> -o jsonpath='{.status.isoDownloadURL}'
```

**Fails if**: InfraEnv never generates an ISO URL within 10 minutes.

### Step 4: Download the discovery ISO

Downloads the full discovery ISO from the Assisted Installer's URL to `/tmp/discovery.iso`. This ISO contains the RHCOS live image + the Assisted Installer agent that will register the VM as an Agent CR.

### Step 5: Upload ISO to vSphere datastore

Creates a directory `<cluster>/` on the configured datastore and uploads the ISO:

```
govc datastore.mkdir -ds=<datastore> <cluster>
govc datastore.upload -ds=<datastore> /tmp/discovery.iso <cluster>/discovery.iso
```

The local ISO is deleted after upload to free pod disk space.

### Step 6: Create control plane VMs

Loops `MASTER_COUNT` times (default 3), creating VMs named `<cluster>-master-0`, `<cluster>-master-1`, etc.

For each VM:
1. **Check if exists** — `govc vm.info <vm-name>`. If it already exists (e.g., Job restarted), skip creation.
2. **Create VM** — `govc vm.create` with:
   - CPU: `vsphereControlPlane.masters.cpus`
   - Memory: `vsphereControlPlane.masters.memoryMB`
   - Disk: `vsphereControlPlane.masters.diskGB` (thin provisioned, pvscsi controller)
   - Network: `vsphereControlPlane.network` (vmxnet3 adapter)
   - CD-ROM: mounted with `[<datastore>] <cluster>/discovery.iso`
   - Folder: `vsphereControlPlane.folder`
   - Resource pool: `vsphereControlPlane.resourcePool`
   - Created powered off (`-on=false`)
3. **Set boot order** — `govc device.boot -vm=<vm-name> -order=cdrom,disk` (boot from ISO first, then disk)
4. **Power on** — `govc vm.power -on <vm-name>` (skips if already powered on)

The VM boots from the discovery ISO, which runs the Assisted Installer agent. The agent phones home to the hub cluster and registers as an `Agent` CR in the `<cluster>` namespace.

### Step 7: Create vSphere worker VMs (if workers.count > 0)

Same process as Step 6 but for worker VMs:
- Named `<cluster>-vsphere-worker-0`, `<cluster>-vsphere-worker-1`, etc.
- Uses `vsphereControlPlane.workers.cpus/memoryMB/diskGB` (can differ from master specs)
- Boots from the same discovery ISO on the same datastore
- Skipped entirely if `WORKER_COUNT=0`

### Step 8: Wait for agents to register

Polls for non-BMH agents every 15 seconds (up to 120 attempts / 30 minutes):

```
oc get agents -n <cluster> -l '!agent-install.openshift.io/bmh'
```

The label selector `!agent-install.openshift.io/bmh` filters out bare metal agents (which have a BMH label). This leaves only agents that booted from the vSphere ISO — exactly the VMs the Job created.

Waits until the count of non-BMH agents >= `MASTER_COUNT + WORKER_COUNT`.

**Fails if**: Not enough agents register within 30 minutes (e.g., VMs failed to boot, network issue, ISO problem).

### Step 9: Approve agents and assign roles + hostnames

Iterates through all non-BMH agents and patches each one:

**For the first `MASTER_COUNT` agents:**
```
oc patch agent <agent-id> -n <cluster> --type merge \
  -p '{"spec":{"approved":true,"role":"master","hostname":"<cluster>-master-<N>"}}'
```

**For the remaining agents (up to `WORKER_COUNT`):**
```
oc patch agent <agent-id> -n <cluster> --type merge \
  -p '{"spec":{"approved":true,"role":"worker","hostname":"<cluster>-vsphere-worker-<N>"}}'
```

Each patch does three things in one call:
1. **`approved: true`** — tells the Assisted Installer this agent is authorized to join the cluster
2. **`role: master/worker`** — assigns the OpenShift node role
3. **`hostname: <name>`** — sets the node hostname (DHCP doesn't always set it on discovery-booted VMs)

Already-approved agents are skipped (idempotent on Job restart).

### Step 10: Exit

The Job exits successfully. At this point:
- All vSphere VMs are running and registered as approved Agents
- The Assisted Installer now waits for `provisionRequirements.controlPlaneAgents` + `provisionRequirements.workerAgents` total agents (including any bare metal workers) before starting the OpenShift installation

## What happens next (outside the Job)

1. Bare metal workers boot via BMC/Redfish from the `-workers` InfraEnv ISO and register as separate Agents (approved automatically by the BMH controller)
2. Once all `provisionRequirements` are met, the Assisted Installer begins the OpenShift installation across all agents
3. The cluster is installed and imported into ACM as a ManagedCluster

## Failure modes

| Failure | Behavior |
|---------|----------|
| InfraEnv ISO never appears | Job times out after 10 min, retries (backoffLimit: 2) |
| vCenter unreachable | govc commands fail, Job retries |
| VM creation fails | govc exits non-zero, Job restarts. Existing VMs are skipped on retry. |
| Agents don't register | Job times out after 30 min waiting for agents |
| Job exceeds 2 hours total | Killed by `activeDeadlineSeconds` |

## Ansible variant

When `vsphereControlPlane.automation: ansible`, the same logic runs as an Ansible playbook instead of a shell script. The steps are identical — the playbook uses `community.vmware.vmware_guest` instead of `govc vm.create`, and `kubernetes.core.k8s` instead of `oc patch`. The ansible runner image is `quay.io/ansible/ansible-runner:latest` (configurable).
